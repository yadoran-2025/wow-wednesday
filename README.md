# 놀라운 수요일

[실제 사이트 열기](https://yadoran-2025.github.io/wow-wednesday/)

`npm start` 후 [원본 앱](http://127.0.0.1:4173/)을 연다. 기존에 검토한 [목업](http://127.0.0.1:4173/mockup/index.html)은 별도로 남아 있다.

## 사용

- 왼쪽 문제를 눌러 편집한다. 제목·정답·음원·구간을 입력한 뒤 **문제 저장**을 누른다. 입력 중인 초안도 자동 보관되며, 문제 저장 여부는 별도로 표시한다.
- 음원 파일은 이 브라우저의 IndexedDB에 저장한다. 새로고침하거나 다시 열어도 복원한다. 복제한 문제의 음원은 원본과 별도로 유지하므로 하나를 삭제해도 다른 문제가 영향을 받지 않는다.
- 링크에는 YouTube URL 또는 직접 재생 가능한 음원/영상 URL을 넣는다. 일반 웹페이지 주소는 음원으로 재생할 수 없다. 영상의 공개·퍼가기 설정이나 브라우저 재생 정책에 따라 재생이 제한되면 **원본 링크 열기**를 사용한다.
- 시작·끝 시간을 정하고 **구간 다시 듣기**를 누른다. 타이머·글자 힌트를 조작해도 플레이어를 교체하지 않는다.
- 힌트는 0.3초 보기·초성·랜덤 한 글자·단어 하나 공개를 제공한다. **힌트 되돌리기**로 마지막 조작을 복구한다.
- 규칙 수정, 타이머 기본 시간, 선택한 문제도 같은 브라우저에 보관한다. 새로 열 때는 준비 화면에서 시작한다.

원본의 문제 자료 링크 3개, `by 현수토리 선생님`, [출처 블로그](https://m.blog.naver.com/PostList.naver?blogId=kimhsu1)를 모든 화면 상단에 유지한다.

## 기존 데이터

처음 실행할 때 같은 브라우저·같은 사이트에 있는 `wow-wednesday-maker-v4`와 `wow-wednesday-audio/audio-files`를 읽어 문제·수정 중 초안·음원·규칙·타이머를 이전한다. 새 저장소는 `wow-wednesday-app`이며 문제와 음원 변경을 하나의 트랜잭션으로 기록한다. 기존 저장소는 지우거나 수정하지 않는다. 이전 데이터가 손상되거나 저장 공간이 부족하면 오류를 표시하고 기존 저장본을 남긴다.

저장은 현재 브라우저와 사이트 주소에 한정된다. 다른 기기와 동기화되지 않으며, 브라우저의 사이트 데이터를 지우면 새 저장본과 기존 저장본 모두 사라질 수 있다.

## 검증

`npm test`는 추가 의존성 없이 시간·한글 초성·힌트 위치·되돌리기·URL 검증·기존 문제 변환을 검사한다.

`npm run test:browser`는 Playwright가 있는 환경에서 실행한다. 별도 설치 위치를 사용할 때는 `PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs npm run test:browser`로 지정한다. 서버는 먼저 실행해야 한다. 필요한 경우 `APP_URL`과 `CHROME_PATH`를 지정할 수 있다.

브라우저 검증은 새 테스트 프로필을 사용한다. 파일·직접 링크 WAV의 실제 구간 재생, 새로고침 뒤 문제와 음원 복원, 복제·삭제 분리, 규칙 보관, 저장 실패·재시도, 기존 데이터 이전, 반응형 배치를 확인한다. YouTube는 [공식 IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)의 시작·끝 인자, 재생 제어, 플레이어 유지 여부를 API 대역으로 검사한다. 실제 영상의 재생 가능 여부는 YouTube와 영상별 설정에 따라 달라진다.

2026-11-07에 원본 앱에서 쓰던 YouTube 영상으로 00:42~00:46 실제 재생, 힌트·타이머 조작 중 재생 유지, 구간 끝 정지를 추가 확인했다. 일반 MIME 형식으로 첨부한 WAV의 저장·복원·재생도 확인했다.
